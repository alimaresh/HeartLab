# المتطلبات والمعمارية

## مطابقة متطلبات المادة

| المتطلب | الدليل البرمجي | ما تعرضه للدكتور |
| --- | --- | --- |
| ES Rule based | `heart_app/rules.py` | قواعد IF/THEN والحقائق وأولوية High ثم Medium ثم Low |
| ML | `heart_app/ml.py` و`heart_app/multiclass.py` | نموذج ثنائي، شجرة قرار، ومصنف مستقل لأربع مجموعات |
| NLP | `heart_app/nlp.py` | النص، الكيانات، النفي، والتحويل إلى حقول |
| GUI PY | `heart_app/gui.py` و`app.py` | نافذة Tkinter وتبويبات الإدخال والنص والتفسير |
| Markdown → MkDocs | `docs/` و`mkdocs.yml` | موقع التوثيق المبني محليًا |

## تدفق البيانات

```text
Arabic / English text
        ↓
Normalization → entity extraction → negation / conflict checks
        ↓
User reviews and applies extracted fields → completes missing fields
        ↓
schema.validate (13 raw fields)
        ↓
service.assess
        ├── rules.infer → matched rules → priority → explanation
        └── ml.predict → saved preprocessing pipeline → class + score
        ↓
Tkinter / Streamlit → results → optional local JSON export (Tkinter)
```

## المكونات

- `schema.py`: أسماء الحقول، المجالات المقبولة والتحقق الموحد.
- `nlp.py`: استخراج رمزي محدود القاموس، دون LLM أو نموذج خارجي.
- `rules.py`: قاعدة المعرفة ومحرك مطابقة القواعد وإرجاع أثر الاستدلال.
- `ml.py`: تجهيز البيانات والتدريب والتنبؤ وحفظ تقرير التجربة.
- `service.py`: نقطة الربط بين الواجهتين والمحركين.
- `gui.py`: الواجهة المكتبية. `ui/app.py`: واجهة ويب اختيارية بنفس المنطق.
- `presentation.py`: ترتيب البطاقات وألوان وعناصر واجهة سطح المكتب.
- `pulse.py`: محاكاة دورية متحركة مشتقة من BPM فقط، مع إيقاف واستئناف الحركة.
- `demos.py`: ثلاث حالات اصطناعية مستقلة عن التدريب.
- `multiclass.py`: تدريب وتقييم المصنف المستقل بست خصائص وأربع مجموعات.
- `multiclass_gui.py`: واجهة القياسات المتوسطة ونتائج المجموعات المرتبة.

لا توجد قاعدة بيانات أو خدمة خلفية أو إرسال لحالات المستخدم إلى الإنترنت.
التطبيق يعرض مخرجي ES وML مستقلين؛ لا يمزجهما في نتيجة طبية واحدة.

## قرارات التصميم

الصفحة الرئيسية تستخدم `questionnaire.py` لربط البيانات و`triage.py` لتوصية المراجعة و`screening.py`
للتصنيف ونسبة تعليمية. النص يُحوَّل إلى اقتراحات يراجعها المستخدم ويطبقها قبل الحساب.
قواعد الأعراض منفصلة عن القواعد العشر المبنية على قياسات؛ لا تقارن أرقام تقييم القواعد القديمة بهذا الاستبيان.
النموذج الأساسي مدرّب على UCI Hungarian باستخدام نبض الراحة؛ شجرة القرار القديمة باقية بالقسم الاختياري.
علامة خطر حالية تتجاوز النموذج مباشرة؛ التصنيف السلبي لا يخفض استعجالًا حددته القواعد.

تم استخدام Python مباشرة لمحرك القواعد لتجنب تبعية Experta القديمة، مع قواعد قابلة للقراءة والتفسير.
الاستدلال الأمامي هنا بسيط: حقائق الحالة → كل قواعد التصنيف المطابقة مرة واحدة → قاعدة أولوية نهائية.
لا توجد قواعد متكررة أو استدلال عكسي أو معاملات يقين؛ هذه ليست خصائص يدّعي المشروع تنفيذها.

واجهة الإدخال تبدأ فارغة، والبيانات التجريبية موسومة بأنها اصطناعية.
تطبيق نتائج NLP يمسح الحالة القديمة حتى لا تختلط قيمها مع وصف جديد.
تغيير الحقول يبطل نتيجة Tkinter السابقة ويمنع تصديرها حتى إعادة الحساب.
