# دليل الاستخدام وخطة عرض المادة

## الواجهة المكتبية

التصميم الجديد يضع بطاقات البيانات والأعراض والوصف على اليمين، والرسم والنتيجة على اليسار.
أزرار التقييم والمسح و**Dummy Data** ثابتة أسفل النافذة، مع تمرير المحتوى عند الحاجة.

### الرسم التوضيحي وDummy Data

إدخال BPM يغيّر عدد دورات الرسم وسرعته مباشرة: 60 تعني دورة واحدة في الثانية، و120 دورتين.
الرسم موجة دورية اصطناعية عبر نافذة أربع ثوانٍ؛ لا يستقبل بيانات جهاز ولا يمثل ECG أو يكتشف اضطراب النظم.
يظل فارغًا دون BPM صالح. زر إيقاف الحركة يجمّد العرض دون تغيير القيم أو النتيجة.

قائمة **Dummy Data** تحمل ثلاث حالات اصطناعية كاملة، ويمكن تعديلها قبل «ابدأ التقييم»:

| الحالة | الغرض من العرض |
| --- | --- |
| دون علامات عاجلة | إظهار حالة مكتملة دون تصعيد عاجل في قواعد الفرز |
| مراجعة الطبيب | إظهار توصية بموعد مع تقدير النموذج |
| تنبيه الطوارئ | إظهار أولوية علامات الخطر الحالية دون انتظار نسبة |

تظهر شارة «بيانات اصطناعية» أعلى التطبيق. لا تُضاف هذه الأمثلة إلى مجموعة التدريب، ولا تمثل حالات مرضى.
«بدء من جديد» يمسح القيم والنص والنتيجة والرسم والشارة.

### إدخال حالة

شغّل `python app.py`. يختار الملف بيئة `.venv` تلقائيًا إن وُجدت حتى يطابق إصدار مكتبة النموذج.

تظهر الصفحة العربية المبسطة بثلاثة أسئلة بنعم/لا: ألم الصدر أثناء المجهود، ضيق التنفس، وارتفاع ضغط الدم.
تحتوي أيضًا العمر والجنس ونبض الراحة BPM وضغط الدم أثناء الراحة في حقلين: الانقباضي والانبساطي (مثل 120/80).
تُقبل الأرقام العربية، وتُراجع القيم وترتيب الضغط. القياسات غير المعروفة تترك فارغة دون افتراض قيم.
العمر والجنس والضغط الانقباضي ينتقلون إلى نافذة الفحوصات عند فتحها أول مرة؛ النبض الحالي لا يتحول إلى أقصى نبض للمجهود.
يشغّل «التقييم المبدئي» نموذجًا جديدًا يستخدم نبض الراحة والضغط، ويعرض توصية المراجعة ثم التصنيف والنسبة.
أجب كذلك عن سؤال علامات الخطر الموجودة الآن؛ إجابة نعم لا تنتظر النموذج أو اكتمال القياسات.
راجع [التقييم والمصادر](assessment.md) لفهم حدود النسبة والفرز.
الإجابات تبدأ فارغة. يمكنك كتابة «أشعر بألم في صدري عند صعود الدرج»، ثم الضغط على
«فهم الأعراض المكتوبة»، ومراجعة النتيجة قبل «استخدام الإجابات المستخرجة».
الأسئلة غير المذكورة تبقى دون إجابة. «التقييم المبدئي» يستخدم الإجابات التي راجعتها.
«بدء من جديد» يمسح الحالة. لا يعرض غياب الأعراض كدليل على عدم وجود مرض.

زر **الفحوصات الاختيارية** يفتح الواجهة التفصيلية بثلاثة تبويبات:

1. **Patient data**: إدخال جميع الحقول؛ زر Load synthetic demo لحالة تعليمية، وClear all لمسحها.
2. **NLP extraction**: كتابة النص، ثم Extract entities لمراجعة الكيانات والأدلة والتحذيرات، ثم Apply reviewed fields.
3. **Results & explanation**: نتيجة ES، وفئة ML، ودرجة النموذج، والقواعد المفعلة مع القياسات.

بعد تطبيق NLP أكمل الحقول الناقصة يدويًا. زر Run ES + ML يرفض المدخلات غير الصحيحة.
نموذج الفحوصات التفصيلية يحتاج 13 خاصية؛ النموذج الأساسي الجديد يستخدم خمسًا أو ستًا. لا تُختلق قيم فحوصات.
يمكن تصدير النتيجة إلى ملف JSON محلي. تغيير البيانات يلغي النتيجة السابقة حتى إعادة التشغيل.

## تصنيف ECG المتوسط

زر **تصنيف ECG** يفتح نافذة منفصلة ويملأ العمر والجنس والنبض من الصفحة الأساسية إن كانت موجودة.
أكمل مدة QRS وفترة PR وفترة QT من تقرير التخطيط، ثم اضغط «تصنيف الحالة».
تعرض النافذة الاشتباه الأولي ودرجات أربع مجموعات: طبيعي، إقفار/احتشاء سابق، اضطراب نظم، واضطراب توصيل/بنية.
قائمة **Dummy Data** توفر ثلاثة صفوف ثابتة من جزء الاختبار لشرح التدفق في العرض.
هذه الدرجات ليست احتمال مرض، والمصنف لا يتخذ قرار زيارة الطبيب؛ استخدم التقييم الأساسي للفرز.
راجع [توثيق المصنف ومقاييسه](multiclass.md).

## عرض مقترح في 7 دقائق

| الوقت | العرض |
| --- | --- |
| دقيقة | المشكلة والأهداف والمتطلبات الأربعة |
| دقيقة | مخطط انتقال النص إلى حقائق ثم ES وML |
| دقيقتان | تحميل المثال، تشغيله، شرح R01 وأولوية High |
| دقيقة | استخراج المثال العربي، عرض النفي والحقول الناقصة |
| دقيقة | تقرير ML وحذف التكرارات ومصفوفة الالتباس |
| دقيقة | التوثيق والاختبارات وحدود النموذج |

## أسئلة متوقعة

**ما الفرق بين ES وML؟** القواعد مكتوبة صراحة؛ الشجرة تتعلم قراراتها من أمثلة موسومة.

**أين NLP؟** في تحويل النص غير المنظم إلى كيانات وحقائق منظمة، مع التطبيع والنفي؛ ليس مجرد عرض النص.

**لماذا لا يُملأ كل شيء من النص؟** الأعراض لا توفر تلقائيًا قياسات المختبر أو رموز الاختبارات؛ إكمالها افتراضيًا سيختلق بيانات.

**لماذا تختلف نتائج المحركين؟** مصادر المعرفة ومهمة التصنيف مختلفة، والقواعد الموروثة ضعيفة وغير متحققة سريريًا.

**لماذا الدقة أقل من 98% القديمة؟** التجربة تغيرت: إزالة التكرارات قبل التقسيم، معالجة موحدة، واختبار جديد.
لا ينبغي مقارنة الرقمين كأنهما على نفس التجربة.

**ما الإضافة الشخصية إلى GitHub؟** NLP وTkinter والتوثيق والاختبارات، وإصلاحات البيانات والمسارات والتفسير وتكامل المكونات.

## ملفات التسليم

الكود و`requirements.txt` و`mkdocs.yml` ومجلد `docs` والاختبارات و`artifacts/metrics.json` وشرح تشغيل التدريب.
استبعد `.venv` وملفات الكاش. أعد بناء النموذج على جهاز العرض قبل بدء المناقشة.
